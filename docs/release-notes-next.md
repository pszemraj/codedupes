# Next Release Engineering Notes

## CLI, output, and cache overhaul

- Split the 1,857-line `cli.py` into a `codedupes.cli` package with frozen option bundles and rich-click help panels for scope, detection, semantic model, device, cache, and output controls. Native paired boolean flags replace independent positive/negative parameters, `-h` is available everywhere, and options accept unqualified `CODEDUPES_*` environment variables such as `CODEDUPES_DEVICE`, `CODEDUPES_MODEL`, and `CODEDUPES_NO_CACHE`.
- Added the explicit semantic progress policy `auto|always|never` across analyzer and low-level embedding APIs. Auto mode requires more than 100 uncached inputs and a TTY; JSON forces `never` and disables Hugging Face progress so merged stdout/stderr remains valid JSON.
- Added `EmbeddingRunStats` to successful semantic analysis/index results and JSON summaries. It reports requested/unique rows, persistent hits, in-run duplicate reuse, actual encode count, model-load status, cache revision/device, and manifest transition/GC activity; terminal checks show one compact `Embeddings` row.
- Added `check --fail-on actionable|all|none`, defaulting to `actionable`. In combined mode, the default fails only for exact, deterministic near, or semantic-plus-traditional (`hybrid_confirmed`) findings; pure-semantic tiers and non-strict unused guesses remain advisory. Raw-mode duplicates and strict-unused findings remain actionable. JSON records both the policy and computed exit code, and terminal summaries show the selected policy and finding status.
- Decoupled traditional matching from semantic candidate selection. Combined and traditional-only checks now run deterministic matching across the same full extraction scope, so `--min-statements` and `--semantic-unit-type` affect embeddings without hiding exact or Jaccard findings.
- Simplified the default tiny-unit filter: it now applies uniformly to functions, methods, and classes and drops every traditional pair whose endpoints are both below `--tiny-cutoff`. `--no-tiny-filter` remains the raw opt-out; the redundant `--tiny-near-jaccard-min` exception is gone.
- Replaced JSON output with schema v2. A top-level `units` map stores each finding unit once by `CodeUnit.uid`; duplicate arrays are edge lists and unused/search results carry UID references, removing quadratic repeated unit payloads in large clusters.
- Added an end-to-end filesystem transition suite covering cold scans, edits, renames, cross-directory moves, deletes, move+edit, identical bodies, caller additions, narrow reruns, and cached-versus-uncached finding parity.
- Added per-shard `manifest.json` corpus metadata. Each candidate selection has an independent baseline and generation, so alternating check/search or changing scope filters does not reset orphan aging or classify filtered units as deleted. Comparable complete scans classify moves/deletes, retain orphaned code rows for three complete generations, compact them only when no selection still references them, and clear orphan age when content returns. Incomplete/narrow scans merge into their selection baseline and never collect, query rows remain under their independent FIFO policy, failed analyses do not publish, and `cache info` reports orphan rows plus the last complete generation.
- Added opt-in `search_document="contextual"` / `--search-document contextual`, which embeds a language/path/symbol/code envelope under a distinct cache variant. The default remains calibrated source-only input; duplicate analysis always stays source-only.

## Polyglot extraction and duplicate analysis

- Added first-class C, Rust, JavaScript/JSX, and TypeScript/TSX extraction behind the existing `CodeExtractor` facade. Python remains on CPython AST; the new languages use exact-pinned official Tree-sitter packages with no runtime grammar download or line-chunk fallback.
- Added canonical language/dialect/native-kind and byte-range metadata to `CodeUnit`, plus backend-computed structural fingerprints, token fingerprints, identifier sets, calls, and statement counts so downstream analysis never reparses non-Python source as Python.
- Added repeatable `--language` filtering with `py`, `rs`, `js`, `jsx`, `ts`, and `tsx` aliases. Automatic `.h` parsing is conservative, and TypeScript declaration files are excluded.
- Traditional exact/Jaccard matching and semantic duplicate checking are same-language by default. Semantic search remains cross-language.
- Unused-code analysis remains explicitly Python-only; mixed-language reports surface the number of excluded non-Python units.
- Added language counts, extraction diagnostics, parser status reporting, and additive language/range fields in JSON output.
- Added parser-independent fingerprint/registry tests and grammar-gated end-to-end extraction fixtures for every new dialect, including golden structural-hash values that pin the fingerprint schema across grammar upgrades.
- `include_private=False` now filters on each language's computed visibility (C internal linkage, Rust `pub` including the enclosing trait's visibility for default methods, TypeScript `private`/`protected`/`#`-fields) instead of a name-prefix subset of those rules. A filtered-out private class now takes its members with it, matching the Python extractor: a method whose owner was never reported no longer leaks out under an unreachable name.
- Rust methods inside an `impl Trait for Type` block are public regardless of a leading `pub`. Trait-impl items cannot legally carry `pub` yet are reachable through the trait, so `--no-private` no longer drops a type's whole trait surface. When the trait is a bare name declared in the same file, the trait's own visibility gates its impl methods instead, keeping private sealed-trait surfaces out of `--no-private` runs; path-qualified and cross-file traits remain public (recall-first, no cross-file resolution).
- C internal linkage is detected from the definition's storage-class specifier instead of a leading-token text match, so `static` functions are correctly non-public while `int dst[static 4]` parameters and interleaved comments no longer confuse the check.
- JavaScript/TypeScript export clauses now mark the local units they name: `export { name }`, `export { name as alias }`, and `export default name` set `is_exported` on the unit declared elsewhere in the file. Re-export clauses naming another module (`export { name } from "./other"`) refer to that module's units and never mark a local unit exported.
- JS/TS unit names and identifier sets are matched with a Unicode-aware pattern. ECMAScript identifiers are Unicode from ES2015 on and Rust accepts non-ASCII identifiers, so non-ASCII names are extracted instead of silently dropped by an ASCII-only regex.
- `jsx_text` is normalized with the other string forms in structural fingerprints: it is display copy, not structure. Fingerprints of JSX components with text children re-key, so two otherwise identical components no longer fail to match because their labels differ.
- Rust functions under `#[cfg(test)]`/`#[cfg(all(..., test, ...))]` modules and free `#[test]` functions are skipped by default; `all` predicate order is irrelevant, and file globs cannot catch inline test modules.
- Rust trait-impl methods carry their trait in the qualified name (`m.W.Display.fmt`, path and generic arguments preserved), so `impl Display for W` and `impl Debug for W` no longer report two units under one `m.W.fmt`.
- JS/TS object-literal and lexical containers resolve through one rule: methods on classes inside object literals keep every segment (`m.registry.Alpha.run`, previously `m.registry.run` for both siblings), and classes declared inside object-literal methods keep the literal's binding path (`m.api.build.Inner`).
- JavaScript/TypeScript export marking stops at function-body boundaries: units nested inside an exported function are no longer reported as exported. Members of an exported class remain exported.
- The structural fingerprint walk is iterative, so deeply nested or minified sources no longer risk Python's recursion limit; the walk change itself left the canonical stream unchanged.
- A declaration's own name now normalizes in structural fingerprints the way Python def/class names do (fingerprint schema 2): renamed-but-identical JS/TS methods and TS classes land in the deterministic renamed tier instead of depending on the semantic tier. Object-literal keys, member accesses, and field names remain preserved as data/API shape, so shape-changing renames still re-key.
- The C-header policy scan prunes exactly the directories default extraction skips, via one shared predicate. A C++ dependency under `vendor/` now disables automatic `.h` parsing because the walk would analyze it; C++ inside `*.egg-info` or other default-excluded directories can no longer flip the decision for files the walk never visits.
- `codedupes info` grammar readiness now constructs each parser and runs an empty parse (memoized per process), so a right-version but unloadable wheel reports its error instead of failing mid-analysis. A missing grammar surfaces in the CLI as a dedicated error naming the pinned package with a pointer to `codedupes info`.
- The registry is the single source of grammar pins (`REQUIRED_PARSER_PACKAGES`); tests enforce that `pyproject.toml` matches it.
- `CodeUnit.structural_hash` and `CodeUnit.token_hash` are plain public fields; the private `_ast_hash` alias is gone. `CodeUnit.uid` uses one form for every language, `<path>::<language>::<qualified>::<start_byte>`, fixing latent identity collisions for overloads and conditional redefinitions. The always-`True` `has_body` field (and its JSON key) was removed.
- Python extraction builds per-file line/byte tables once instead of re-encoding the file for every emitted unit.
- Added per-language duplicate calibration corpora under `test_fixtures/polyglot_calibration/` for C, Rust, JavaScript, TypeScript, and an alpha-renamed Python control: seven validator-enforced clone categories (including docstring/comment `doc_variant` pairs), hard negative controls, and labeled search probes per language, ~100 labeled decisions each. A tracked validator (`scripts/validate_calibration_corpus.py`) enforces each category's fingerprint contract mechanically, rejects every parse or recovery diagnostic, and reports production candidate coverage, while `scripts/report_calibration_distributions.py` records per-category cosine distributions for both built-in models. The sweep harness is language-aware (`--language`, `--duplicate-start`/`--duplicate-stop`, corpus digests cover non-Python files), defaults to the production three-statement candidate floor, scores final combined output, allows full-scope traditional analysis to recover labels outside the semantic candidate pool, and records duplicate/search candidate coverage in each manifest. Recorded per-language threshold measurements live in the corpus README.
- Semantic duplicate detection is now gated per language: each built-in profile carries calibrated gates derived from the polyglot corpora with recall-first selection (gte-modernbert-base: python `0.80`, c `0.82`, rust `0.74`, javascript `0.70`, typescript `0.68`; embeddinggemma-300m: python `0.74`, c `0.78`, rust `0.78`, javascript `0.72`, typescript `0.78`), replacing the single flat duplicate thresholds (`0.96`/`0.86`) that only reached deterministic-shaped clones outside the leaky legacy Python corpus. The profile fallback for uncalibrated languages is the strictest calibrated gate; an explicit `--semantic-threshold`/`--threshold` still applies one flat gate everywhere. The pairwise scan partitions candidates by language and scans each group at that language's own gate, so one loosely gated language no longer drags every other language's scan down to the floor and builds pairs that are discarded moments later; the scalar floor covers only languages that reach the scan without a calibrated entry, and an opted-in cross-language pair is held to the looser of its two gates.
- The embeddinggemma typescript gate was tightened from `0.76` to `0.78`. A shipped gate may sit below the sweep's F1 pick wherever the sweep shows recall gains below it, but `0.76` was two grid steps loose on flat recall: it doubled on-corpus false positives for no measured recall. Flat-recall loosening is now capped at one grid step, as an off-corpus generalization hedge, and `tests/test_calibration_reports.py` holds every gate to recall at or above the selection's with F1 within 80% of it.
- Semantic inputs that exceed the selected model's context window are still never embedded from a lossy head-only prefix, and the guard now measures exactly what the backend tokenizes - the encode prompt plus the text - so inputs near the limit that previously slipped through prefix truncation are caught. An over-context corpus unit is now skipped with a warning and a `semantic-context-overflow` diagnostic and the run proceeds, instead of aborting the whole analysis; the embedding matrix and the candidate list drop the same rows, so pair mining stays aligned. `--allow-semantic-fallback` is not involved. An over-long `search` query still fails hard, because a truncated query has no result to omit. Older prefix-truncated cache rows remain invalidated.
- Built-in semantic/search thresholds now fail closed outside their calibrated revision, prompt plan, and remote-code setting. Alternate EmbeddingGemma tasks, custom instruction prefixes, alternate built-in revisions, and a `trust_remote_code` value differing from the profile default require an explicit threshold - remote code can change the vectors, which already splits the embedding cache key, so it must invalidate the calibrated duplicate gates and the search default too. Prompt-sensitive direct search also requires the corpus identity returned with its embeddings.
- Hybrid synthesis no longer has a separate semantic-only minimum (`0.92`): a semantic pair's presence is the evidence it cleared its per-language gate. Identifier-overlap and statement-ratio corroboration promote semantic-only pairs to `semantic_high_confidence`; alpha-renamed or structurally different pairs remain visible as `semantic_review` instead of being discarded. `scripts/sweep_hybrid_gates.py` now sweeps the gate by pre-filtering semantic pairs (its `--hybrid-semantic-threshold` flag is gone); raw candidates are collected at the lowest `--semantic-grid` value so every grid row is reachable, an explicit `--semantic-threshold` above that floor is rejected, and the script now takes the same `--device` pin as the semantic sweep (default `cpu`) so regenerated reports stay on the CPU/float32 baseline.
- Hybrid confidence is now an explicit corroboration scale rather than a raw similarity: `exact` `1.0`, `traditional_near` `0.55 + 0.45 * jaccard`, `hybrid_confirmed` `0.5 * semantic + 0.5 * jaccard`, `semantic_high_confidence` `0.45 + 0.55 * semantic`, and `semantic_review` `0.40 + 0.45 * semantic`. `semantic_review` previously carried its raw cosine and could outrank corroborated tiers; it now sits strictly below `semantic_high_confidence` at every similarity (the gap is `0.05 + 0.10 * semantic`), so the weakest tier can no longer crowd the best-evidenced pairs off the top of the table.
- New opt-in `--cross-language` (`AnalyzerConfig.cross_language`) reports semantic duplicate pairs across languages; these claims are uncalibrated, so a mixed pair is held to the looser of its two language gates. Default output remains same-language only.
- Traditional exact and Jaccard blocking now groups functions and methods into one `callable` kind, so code moved between module level and a class body is comparable across the function/method boundary instead of being blocked apart from its original. On the numpy benchmark corpus this raised near-duplicate participation from 23 to 207 pairs. Exact matching remains same-language: aligned canonical token streams still cannot make a C and a Rust function exact duplicates.
- Extraction now diagnoses files it passes over instead of dropping them silently: one summary `c-header-policy` diagnostic per directory scan naming how many `.h` files the conservative header policy skipped and suggesting `--language c`, plus `unsupported-file`, `language-filter`, and `declaration-file` diagnostics for files named explicitly on the command line.
- `filtered_raw_duplicates` is gone from `AnalysisResult` and from every CLI surface (terminal summary row, `check --json` summary key, `--show-all` hint text). Once every semantic-only pair began falling back to `semantic_review`, no candidate pair could reach no tier, so the count was structurally zero. `_synthesize_hybrid_duplicates` now returns only the hybrid list.
- `check --json` now reports `semantic_diagnostics` as both a `summary` count and a top-level array, in combined and single-method modes alike, using the same entry shape as `extraction_diagnostics` (`file`, `language`, `severity`, `code`, `message`, `line`, `end_line`). `search --json` gained the same top-level array, so a search that silently skipped an over-context unit says so. The terminal summary adds a `Semantic diagnostics` count row and prints the first ten entries.
- The traditional-only terminal panel is titled `Traditional Duplicates (Structural/Token/Jaccard)`. The tier has never been AST-specific - Python is the only backend using an AST, and the fingerprints are language-neutral.
- Python files are read as bytes: a UTF-8 BOM no longer fails the parse (offsets shift over it), CRLF survives decoding so `start_byte`/`end_byte` are exact into the on-disk file (the contract the Tree-sitter backends already met), and an embedded NUL byte (a `ValueError` on CPython 3.11) lands in the `parse-error` diagnostic path instead of crashing. The reference-graph alias/`__main__` readers use the same BOM-tolerant read, so a file extraction accepts cannot silently lose its references and surface false unused reports.
- Unreadable files (dangling symlinks, missing permissions, files removed mid-run) emit a `read-error` diagnostic and are skipped instead of aborting the whole analysis; non-UTF-8 Tree-sitter-language files are still analyzed but emit an `invalid-utf8` diagnostic instead of silently flowing U+FFFD into fingerprints, identifier sets, and embedding text.
- Directory walks are sorted, so unit order - and the JSON `units`/`potentially_unused` arrays - is reproducible across filesystems.
- Rust extraction resolves preceding attributes through `prev_named_sibling` instead of a per-ancestor linear sibling scan (2.9s to 0.22s for a 3000-item file, byte-identical units), so generated bindings-style files no longer take minutes.
- Traditional Jaccard near-duplicate detection replaced its all-pairs Python scan with an exact prefix-filtered similarity join - identical pairs, scores, and order, enforced by randomized equivalence tests against the old algorithm: 55.6s to 0.42s at 8000 units under the default threshold. This cost recurs on every `check` (the traditional tier has no cache), so it dominated warm runs.

## Breaking baseline change

- `AnalyzerConfig` gained an explicit `mode` field (`"check"` default, `"search"`). Check-mode configs reject an uncalibrated gate context (custom instruction prefix, non-default EmbeddingGemma task, off-profile revision, non-default `trust_remote_code`) without an explicit `semantic_threshold` at construction — a usage error before extraction or model load — instead of after extraction. Python API callers driving `index()`/`search()` with such a context must pass `mode="search"`, which defers to the independently calibrated query-time search contract; `analyze()` rejects search-mode configs. The `search` CLI command builds search-mode configs itself.
- The embedding pipeline schema is now 5: over-context inputs are rejected or skipped instead of silently truncated, and schema-4 shards could still hold truncated vectors for texts within one prompt length of the context limit. Every existing embedding cache re-embeds on first use; all calibration reports were regenerated under schema 5 with unchanged selected thresholds.
- `CodeExtractor.extract_from_file` now honors `include_stubs=False` for `.pyi` files (previously force-included, making the flag unenforceable on that path) and reports a `stub-policy` diagnostic. The explicit-target opt-in lives in the analyzer instead: a `.pyi` named directly as the analysis target is analyzed as given, matching the documented CLI contract.
- Default semantic duplicate gating changed: the flat per-model thresholds (`0.96` gte / `0.86` gemma) are gone, replaced by the calibrated per-language gates described above. Runs relying on the old flat defaults now get looser, per-language gating unless they pass an explicit `--semantic-threshold`. The hybrid semantic-only `0.92` floor and the `--hybrid-semantic-threshold` sweep flag were removed with it.
- `CodeUnit.uid` uses the universal `<path>::<language>::<qualified>::<start_byte>` format for every language; the private `_ast_hash` alias and the always-`True` `has_body` field (including its JSON key) were removed.
- Minimum PyTorch version is now `2.13.0`; the supported range is `>=2.13.0,<3`. Dev and rc builds of an in-range release (for example `2.13.0.dev20250101`) are accepted.
- The supported Transformers range is now `>=5.1,<6`; validated against Transformers 5.14.1 with sentence-transformers 5.6.1.
- `packaging` is now an explicit runtime dependency because semantic compatibility checks import it directly.
- The minimum `click` version is now `8.2.1`: click 8.2 fixed the resolver bug that turned path-like tokens (`codedupes .`, `codedupes ./src`) without a subcommand into help with exit code zero, letting codedupes drop its partial workaround.
- Semantic startup now rejects an unsupported PyTorch runtime even when dependency resolution was bypassed with `--no-deps` or an editable/source-only environment.
- Removed the C2LLM profile and its DeepSpeed-only `gpu` extra. The backend's separate dependency/runtime contract was not reliable under the supported Transformers baseline; the built-in model set now focuses on `gte-modernbert-base` and `embeddinggemma-300m`.
- Removed the undocumented `semantic_profiles.resolve_model_name()` wrapper. Use `resolve_model_profile(...).canonical_name`.
- Renamed `--min-lines` to `--min-statements` (Python API: `min_semantic_lines` to `min_semantic_statements`): the semantic candidate gate counts executable statements - now recursively through control-flow bodies, with nested functions and classes counting as one declaration - so a large function implemented inside one `try`/`with`/loop block is no longer measured as a single statement and silently skipped.
- VCS-less source snapshots now build with an explicit `0.0.0+unknown` fallback; tagged Git builds continue to derive the release version from VCS metadata. The sdist uses an explicit release-file allowlist containing the package, tests, docs, scripts, and tuning fixtures, so ignored local worktrees cannot leak into published archives.
- Cache-revision keying for unpinned hub models (no pinned profile, no explicit full commit hash) is now loose by default: the cache key is the requested revision *label* itself (the explicit `--model-revision` value, or `main`), never a resolved commit, and persistent caching is not disabled merely because a ref is symbolic. Previously an unpinned revision resolved through the offline Hugging Face cache and, after loading, was double-checked against the loaded commit; a branch move (even a metadata-only commit) rotated the key and invalidated the whole cache, and a symbolic ref that could not be mapped offline silently disabled caching for the run. The trade-off under the new default is bounded by a per-shard source-commit guard: every label-keyed shard records the commit its vectors came from *inside the atomically switched shard index*, so provenance and the vector generation it describes publish as one unit and can never desynchronize on disk. Any run that loads the model - the only runs that could mix checkpoints - compares the loaded commit against that record *and* against the provenance its cache lookup carried out of the shard snapshot it actually read: drift purges the shard and re-embeds; provenance-less hits are rejected; a backend that cannot report its loaded commit forces a complete corpus recompute with cache writes disabled for that call; pre-load hits whose snapshot provenance does not match the loaded commit are discarded even when a concurrent run already republished the shard under that commit; an uncached query that discovers drift aborts with a reindex error instead of comparing across the move; a warm query hit is accepted only when its shard snapshot's provenance matches the source commit recorded with the corpus identity, and a query load whose commit differs from that recorded corpus commit raises for a reindex, so a shard republished by a concurrent process can never slip a new-checkpoint query vector under an old-checkpoint matrix; and a writer whose shard was re-confirmed under a different commit while it was still encoding has its batch rejected under the shard write lock rather than merged. A moved branch can therefore serve coherently *stale* vectors to fully warm runs within one process, but never a matrix mixing two checkpoints; run `codedupes cache clear --model <name>` to drop stale vectors immediately after a known upstream change. Pass `--strict-revision-cache` (Python API: `strict_revision_cache=True` on `AnalyzerConfig` or the semantic functions) to resolve mutable refs to concrete commits before reuse and use that same commit as the model-load key, preventing a process-wide singleton from surviving a branch move. Built-in profile pins and an explicit full commit hash key identically in both modes; local model directories are unaffected (content-fingerprint keying). See [Embedding cache](caching.md#what-invalidates-what).

## Semantic runtime changes

- Added explicit `auto`, `cpu`, `cuda`, and `mps` selection for both CLI workflows and the Python API.
- Added pre-import MPS unsupported-operator fallback control; `codedupes info` configures the fallback environment before importing torch so diagnostics do not pin the setting for later same-process runs.
- Added an optional, validated MPS per-process memory fraction. The fraction is ignored (with a log message) when the resolved device is not MPS, so `--device auto --mps-memory-fraction X` is safe on CPU-only and CUDA hosts. Because the PyTorch setting is process-global, resolving away from MPS now restores the environment/default high-watermark ratio immediately (never merely on a later MPS-resolving call) instead of leaving a codedupes override stuck for the rest of a long-lived process, and fully cache-covered runs and warm query hits - which never prepare a device - restore a pending managed cap the same way when their configuration leaves the fraction unset; the restore never imports torch or touches its allocator unless a custom fraction is actually pending and this build already has MPS support.
- Scoped model cache entries by vector-affecting dtype rather than device and serialized model lifecycle/inference across threads. CPU and MPS float32 EmbeddingGemma runs share cached vectors, while CUDA bfloat16 vectors remain separate.
- Every model load pins an explicit inference dtype (passed as `dtype`, replacing the deprecated `torch_dtype`) under a capability-gated policy instead of a hardcoded per-device truth. Transformers 5 defaults to the checkpoint's declared dtype, which had silently run the default profile in float16: ~10x slower on CPU and off the documented float32 tolerance. CUDA with native bf16 support (Ampere or newer) pins bfloat16 for every family, unchanged. MPS pins float32, unchanged (measured: bf16 gains only ~13% runtime while drifting pair similarities ~1e-2, not worth splitting the shared key space). CPU pins float32 by default; the experimental `CODEDUPES_CPU_BF16=1` opt-in enables bfloat16 when this machine also passes a two-part gate - a native bf16 ISA (`bf16` on ARM, `amx_bf16`/`avx512_bf16` on x86) *and* a GEMM backend able to exploit it (`torch.backends.mkldnn.is_available()`) - never `torch.backends.cpu.get_cpu_capability()`, which reports a build-tier baseline, not runtime capability. The opt-in guard exists because the positive path is unvalidated: the duplicate/search thresholds are calibrated under float32 and no gate-passing machine has yet validated speed and decision parity, so automatic CPU bf16 waits for that evidence. Measured on an Apple M5: a native bf16 ISA is present but this build has no mkldnn backend, so a 1024x1024x1024 bf16 matmul measured 841x slower than float32 (1015 ms vs 1.207 ms) - the gate exists so a future mkldnn-capable machine gets the real benefit instead of this negative result being hardcoded forever. The gate probes live, at most once per process, and persists nothing: an opted-in run reads the torch capability APIs directly on first use and memoizes the verdict, so a replaced same-version torch wheel, a changed container CPU mask, or a migrated environment can never serve a stale verdict from disk; a run without the opt-in never imports torch for the decision. `codedupes info` reports the live CPU name, architecture, ISA flag, mkldnn availability, combined verdict, and effective inference policy. Pipeline schema unchanged - dtype-variant key spaces are only split further for opted-in gate-passing machines, never remapped, so every default run keys byte-identically to before. See [Accelerators](accelerators.md#precision-and-metal-environment-variables).
- Every accelerator-to-CPU fallback - the OOM batch-halving ladder's last resort, and a load-time OOM retry (now covering CUDA, previously MPS-only) - re-checks the CPU bfloat16 inference policy above: bfloat16 is cast to float32 unless the opt-in is set and the gate passes; a load-time retry re-pins the CPU dtype fresh rather than blindly inheriting the accelerator's dtype. A run keyed under a bfloat16 dtype variant whose live execution can no longer produce bfloat16 discards any cache hits and restarts the whole corpus under one coherent policy (mirroring the fast-math precedent below), and skips any write that would otherwise land in the wrong key space.
- A `PYTORCH_MPS_FAST_MATH`-keyed corpus run that executes off MPS (unavailable accelerator, or the OOM fallback) discards partial fast-math state and rebuilds the complete matrix under the faithful CPU cache identity. Analyzer queries follow that effective identity; standalone queries that leave fast math abort before the dot product.
- Fixed a stale-device bug in the cache-dimension-mismatch re-encode path: it previously replayed the execution device captured before the first encode call, which could misclassify a later CPU allocator failure as an accelerator OOM after a mid-encode fallback. It now re-reads the live device.
- Added MPS memory diagnostics, synchronized allocator cleanup, adaptive batch-size OOM retries, and one final CPU retry. The CPU retry restarts from the originally requested batch size capped at 32 (`CPU_FALLBACK_MAX_BATCH_SIZE`) and re-enters the halving ladder if host memory also OOMs; the cap exists because host OOM can arrive as an uncatchable OOM-killer kill the ladder never sees (observed live on WSL2 with a 512-batch CUDA request), so an accelerator-sized batch must not carry over to the host; the invalid-output CPU retry (NaN/Inf accelerator vectors) restarts from the same capped size for the same reason. MPS `Invalid buffer size` failures (a single tensor above Metal's per-buffer cap) recover through the same ladder.
- Made MPS-to-CPU OOM fallback state explicit so later calls do not falsely report MPS execution; reusing the fallback model for an accelerator request warns once per fallback event.
- Python API callers no longer get dependency log spam: model loading quiets known-noisy third-party loggers (httpx, transformers, sentence-transformers, huggingface_hub, and friends) when they still inherit the root level, so a bare `logging.basicConfig(level=logging.INFO)` shows codedupes progress without HTTP request lines; explicitly configured loggers are never overridden. The list and an explicit `quiet_dependency_loggers(level)` helper are exported; the CLI keeps its existing behavior through the same helper. See [Python API](python-api.md#logging).
- `CodeAnalyzer.search(query, top_k=10, threshold=None)` takes a per-call threshold that overrides `config.semantic_threshold` for that query only. Previously the only way to raise a search floor from the Python API was `config.semantic_threshold`, which also flattens every calibrated per-language duplicate gate for the same analyzer.
- Search-query embeddings are no longer cached when the corpus identity carries a mutable revision label and no resolved source commit. The corpus bypassed its own shard in that case, so there is no commit a cached query row could be tied to; reads and writes now bypass with it rather than risk serving a row written under another checkpoint of the same branch.
- Distribution reports (`scripts/report_calibration_distributions.py`) now embed the same calibration identity manifest the sweep records, with `mode="distribution"`, and pin the model commit. The per-category distributions are cited as evidence for the shipped gates but previously carried no resolved revision, pipeline schema, embedding space, or corpus digest.
- Gave `search` its own default threshold. Model profiles now carry a search threshold (`0.50` for `gte-modernbert-base`, calibrated against real corpora on Apple Silicon; `0.40` for `embeddinggemma-300m`, recall-calibrated against held-out multi-domain probes after the prompt-pipeline fix) separate from the duplicate threshold, so default searches return ranked matches instead of nothing; explicit `--threshold`/`--semantic-threshold` overrides still win. The opt-in search smoke suite exercises every built-in profile.
- Pinned both built-in profiles to immutable model commits and tied every calibrated threshold to a committed calibration manifest (pinned commit, pipeline schema, runtime fingerprint, encode plan, effective embedding-space identity, candidate policy, corpus/label digests) regenerated by `scripts/sweep_semantic_thresholds.py`, which now also sweeps search thresholds against labeled probes and refuses to calibrate unpinned models. The manifest records the analyzer's effective embedding-space identity verbatim next to the requested device rather than re-deriving device and dtype from the request, so a sweep whose accelerator request falls back and restarts on CPU records the CPU-float32 identity instead of labeling those thresholds as CUDA-bfloat16/MPS results, and an active `PYTORCH_MPS_FAST_MATH` policy shows up through the identity's runtime variant. Family-lookalike models (fine-tunes, local copies) keep family loading/prompt behavior but no longer inherit calibrated thresholds; they use the generic defaults unless an explicit threshold is passed, and they now log a warning naming the per-language gates they forgo and the generic `0.82` gate they use instead, once per model per process.
- Model alias reporting lists every key and canonical name once, even if a custom profile repeats one in its alias tuple.
- Prompts are now backend configuration, not text decoration: codedupes passes raw code/query text to Sentence Transformers together with an explicit prompt and encode route (EmbeddingGemma retrieval uses `encode_document`/`encode_query`; duplicate detection uses the symmetric route with the task prompt), so a model's saved prompts can never be applied a second time on top of a manually prefixed input. EmbeddingGemma vectors changed as a result, thresholds were recalibrated, and the embedding cache re-keys automatically. See [Model profiles](model-profiles.md#taskprompt-behavior-by-model-family).
- Embedding cache identity now covers the whole pipeline: encode plan (route and prompt), embedding pipeline schema, and installed sentence-transformers/transformers/tokenizers/torch versions. Upgrading any of them is a clean full-corpus re-embed - one cached matrix can never mix vectors from two library or prompt configurations.
- Local model directories are fingerprinted by file contents (digest manifest keyed on full stat identity, so unchanged files never rehash), and every local-model load is verified by pre-/post-load fingerprints: a directory swapped mid-load reloads once from the current on-disk state, and cache keys always describe the weights actually loaded. The fingerprint walk now follows symlinks (guarded against cycles), so weight shards stored behind a symlinked subdirectory move the fingerprint too; previously they were silently skipped and a weight swap behind a symlink could serve stale vectors.
- Indexed search matrices retain their canonical model, concrete revision/local-content fingerprint, and vector-affecting runtime identity. `search()` verifies that identity before using a cached query and again after loading a model for a query miss, requiring reindexing instead of silently comparing vectors from different coordinate systems.
- The dot product is now the enforced execution-space boundary, not just the cache key. A corpus that restarted faithfully on CPU after an accelerator coherence break records its CPU identity and stays directly searchable - the query-space check retries the recorded CPU policy for every accelerator request, not only MPS fast math, so a CUDA-bf16 corpus rebuilt as CPU-float32 no longer raises "reindex" forever. Conversely, a query encode that falls back mid-run and casts to float32 against a corpus keyed bfloat16 aborts before the similarity comparison (the compatibility check now reads the live model parameter dtype, which the requested-policy identity rebuild could never see); previously only the cache write was suppressed while the invalid comparison still ran.
- Fresh model output is validated centrally before caching or comparison: wrong shape fails immediately, NaN/Inf or zero vectors on an accelerator retry once on CPU, all rows are unit-renormalized, and a corrupted (non-finite) similarity can never be reported as a duplicate. Cached rows carry per-row digests re-verified on read, so on-disk mutation degrades to a per-key miss and self-heals.
- `search` builds its corpus through the new linear `CodeAnalyzer.index()` path - extraction plus embeddings only - instead of running a full `analyze()` whose all-pairs duplicate scan was discarded; searching an empty corpus now returns no results instead of erroring.
- Kept semantic embeddings as normalized NumPy arrays immediately after inference.
- Added MLX coexistence diagnostics without importing or mutating the MLX allocator.
- Avoided forced MPS fast math, forced Metal matmul selection, and success-path cache clearing.
- Added a persistent, content-addressed embedding cache with partial updates, generation-safe concurrent rebuilds, bounded storage (whole-shard LRU eviction against a global byte cap plus a FIFO cap on cached search queries; a narrow run never deletes vectors for units outside its own path or filters), and CLI management. Poisoned (NaN/Inf) rows self-heal on the next recompute, shard deletion by eviction or `cache clear` respects the per-shard writer lock, and temp files orphaned by a killed writer are reclaimed by the next write. See [Embedding cache](caching.md).
- Explicit `--device cuda`/`--device mps` requests are validated even when a fully warm embedding cache makes inference unnecessary or extraction finds no semantic units to embed, for every model family: an unavailable accelerator errors instead of silently serving cached vectors (or an empty result). The check covers `check` on a corpus with nothing to extract, whose empty result returns before the semantic layer runs at all; only a combined-mode `--allow-semantic-fallback` opt-in downgrades it to the same warning a populated corpus would get. Unsupported device names raise the documented `SemanticBackendError` from the semantic Python API instead of a raw `ValueError`, and `find_similar_to_query` on an empty corpus returns no results without loading the model.
- The never-fatal cache contract now covers unreadable state: a cache tree the account cannot stat degrades to a miss, and `cache clear`, statistics, and eviction skip past an unreadable shard instead of crashing or stopping the sweep.
- The never-fatal cache contract now also covers cache construction itself: a failure resolving the cache root (for example `Path.home()` raising when `HOME` is unset) degrades to the same disabled cache used by `CODEDUPES_NO_CACHE` instead of crashing analysis.
- `CODEDUPES_CACHE_MAX_MB` now rejects `0`, negative, and fractional sub-1-MB values the same way it already rejected unparsable ones (warn once, fall back to the 2048 MB default) instead of silently clamping them up to a thrashing 1 MB cache; accepted values are floored to whole megabytes.
- Hardened offline loading for local `save_pretrained` and complete `hf download` directories across `check` and `search`, including family detection for hash-named cache snapshots, early validation of incomplete downloads, and true-case path canonicalization so differently-cased spellings of one model directory share one cache identity on case-insensitive filesystems. See [Model profiles](model-profiles.md#local-model-directories-and-offline-use).
- The pairwise semantic duplicate scan thresholds in NumPy on stable full-width row-block products instead of walking every pair in Python: 3.5s to 0.08s at 8000 units with identical pairs, scores, and order. Strict-lower-triangle masking and bounded column candidate blocks keep dense low-threshold scans from materializing every passing coordinate at once, while a Python-float recheck preserves the exact requested gate. Regression coverage uses random float32 vectors across the 500-row boundary and also covers NaN/inf rows, cross-language gates, exclusions, threshold-rounding edges, stable order, and dense candidate bounds. Cache-covered warm runs are no longer dominated by the scan.
- Embedding input text and exact token hashes normalize line endings, so a CRLF checkout shares cache/vector identity and exact-token duplicate identity with its LF twin instead of splitting the cache or losing a mixed-EOL pair. No embedding pipeline schema bump: cache keys are content-addressed on the prepared text, so existing LF entries stay valid and CRLF units re-key once.

## CLI output and error reporting

- stdout carries report output only: errors, parser-unavailable remediation, and all log output (progress lines and warnings) go to stderr, so a failed `--json` run writes nothing to stdout and piped rich output contains only the report.
- The combined-mode semantic failure message interpolates its cause. Previously the root error ("model not found", an unsupported torch version, an unavailable accelerator) was reachable only through `--verbose`, which `--json` rejects, so CI runs could never see it.
- `search` reports how many units it embedded: an empty index prints a stderr warning that distinguishes no extracted units, semantic eligibility filtering, and context-window exclusions; terminal mode prints semantic diagnostics when present, and `search --json` always carries `indexed_units`.
- Duplicate, unused, and search tables show the shorter of cwd-relative and absolute paths instead of basenames, preserving cross-directory identity without truncating the filename from deep working directories. Rich markup characters in locations and diagnostics are escaped, so dynamic-route segments such as `[id]` render literally.
- `cache info` and `cache clear` errors go to stderr, and `cache clear` exits 1 when any best-effort shard deletion fails instead of reporting a successful zero-entry clear while state remains.
- `cache clear --model` warns on stderr when the target is a local model directory that no longer exists: its shard identity keys on the resolved directory path, so a scoped clear cannot match and previously reported a successful no-op.
- The `--tiny-cutoff` default derives from the analyzer constant instead of a duplicated literal, and `search` handles a path deleted between validation and indexing with the same clean error as `check`.

## Static-analysis fixes

- Identifier normalization now filters Python's actual built-in names through the `builtins` module. Traditional Jaccard and hybrid scores can therefore change for code that uses built-in functions or types.
- Reusing a `CodeAnalyzer` now clears corpus-specific state before each analysis, so an empty or nonsemantic run cannot leave stale embeddings available to `search()`. See [Python API](python-api.md#semantic-query-search).
- Any path-like token (absolute, `.`, `./relative`, `~/home-relative`) passed without the required `check` or `search` command now produces a CLI usage error instead of help with exit code zero, on every supported click version.
- `--traditional-only --no-cache` is accepted as a no-op instead of rejected as a contradictory semantic setting.
- Combined mode now excludes exact duplicates from semantic/hybrid output using the same either-hash rule traditional detection uses to pair them, so an exact pair suppressed by the tiny filter can no longer resurface as a lower-confidence semantic finding.

## Validation boundary

MPS is validated on real Apple Silicon hardware only; the suite contains no simulated MPS. What `tests/test_semantic_mps.py` exercises, and when it may skip, is described in [Accelerators](accelerators.md#hardware-validation).

CUDA gets the same treatment in `tests/test_semantic_cuda.py`, which runs automatically wherever `torch.cuda.is_available()` is true: native-only bfloat16 selection, cold inference and CPU agreement, real allocator OOM through load-time fallback and the capped batch ladder, coherent float32 rebuild of a keyed-bfloat16 corpus, and the query-side abort before the dot product. This suite is the CUDA release gate; the bfloat16 cases skip on pre-Ampere hardware, where CUDA keys as float32.

For this release the hardware suite passed on an Apple M5 (32 GB unified memory, macOS Tahoe, PyTorch 2.13.0). On the same machine, a full `codedupes check` of this repo ran roughly 38x faster on MPS than on CPU and reported the same duplicate pairs on both devices (raw similarities agree to about 2e-4 - CPU and MPS float32 kernels round differently), and strict `--no-mps-fallback` runs completed without hitting unsupported operators.
