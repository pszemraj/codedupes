# Next release

## Migration

- `--exclude` now extends default test exclusions for directory scans and matches directory descendants. Explicit file targets bypass default test patterns but honor custom exclusions. See [extraction scope](analysis-defaults.md#extraction-scope-defaults).
- Directory scans inside a git work tree now skip whatever git ignores (nested `.gitignore` files, `.git/info/exclude`, and the global excludes file, as reported by `git ls-files --ignored`). Pass `--no-gitignore` or `AnalyzerConfig.respect_gitignore=False` to scan those paths; an ignored directory or file selected directly is still analyzed. See [extraction scope](analysis-defaults.md#extraction-scope-defaults).
- JSON consumers must adopt [schema v4](output.md#json-schema-v4): exact duplicates arrive as `exact_families[]` records (one per set of copies, with `method`, `members`, `lines`, and `redundant_lines`) instead of pairwise `exact` edges, pair records lose `has_exact`, and the summary counts findings, where a family counts once (`hybrid_duplicates`, `reported_duplicates`, `truncated_duplicates`, `actionable_duplicates`, `duplicates_by_tier.exact`), with `exact_family_members`, `reported_unused`, `truncated_unused`, and `max_unused` added.
- `CodeUnit.uid` now includes language and start byte. The private `_ast_hash` alias, `has_body`, `AnalysisResult.filtered_raw_duplicates`, and the `AnalysisResult.exact_duplicates` alias (which returned every traditional pair, near-duplicates included, not the `exact` tier) were removed; read `traditional_duplicates` or filter `hybrid_duplicates` by `tier`. See [result types](python-api.md#key-result-types).
- `--min-lines` / `min_semantic_lines` became `--min-statements` / `min_semantic_statements`. The redundant `--tiny-near-jaccard-min` exception and `--hybrid-semantic-threshold` sweep flag were removed.
- Flat duplicate defaults were replaced by [per-language gates](analysis-defaults.md#semantic-duplicate-gate-defaults). Pass `--semantic-threshold` (or `AnalyzerConfig.semantic_threshold`) to retain a flat semantic policy.
- `codedupes check` now [withholds `semantic_review` pairs by default](output.md#report-selection). Consumers that require every hybrid edge should add `--include-review`.
- The default `check` report, terminal and JSON alike, now lists at most 20 primary duplicate findings, exact families first (ranked by the lines a consolidation would remove) and then actionable tiers, and at most 20 potentially-unused units ranked largest first; `--json` used to emit every default-visible pair and every unused unit while the terminal showed 20 of each. Add `--max-duplicates all` and `--max-unused all` to restore the complete lists, or `--show-all` for every hybrid tier plus the raw lists; `--include-review`, `--show-all`, and `--full-table` lift both caps unless an explicit value is given, and `--full-table` no longer bounds the unused table itself. `check_result_to_json` now requires `strict_unused`; `ReportSelection` gained `exact_families`, `truncated_exact_families`, and `truncated_unused`. See [report selection](output.md#report-selection).
- Default unused reporting now also [skips public methods of public classes](analysis-defaults.md#potentially-unused-defaults); pass `--strict-unused` to keep them. `build_reference_graph` and `find_potentially_unused` moved to `codedupes.unused`, and `run_traditional_analysis` returns `(exact, near)` only.
- The old case-insensitive substring check over unit source (`# noqa: codedupes` and `# codedupes: ignore` anywhere, strings and docstrings included) is gone; suppression is now a single [comment-only directive grammar](analysis-defaults.md#suppression-directives), `codedupes: ignore` with an optional `[unused]`/`[duplicates]`/`[unused, duplicates]` kind list, attached to a unit's header or a contiguous leading-comment block and inherited by nested units but never by a container. `# noqa: codedupes` no longer suppresses anything. `CodeUnit.suppressions` records the resolved kinds. `build_reference_graph` now returns `list[ExtractionDiagnostic]` instead of `None`, and `run_unused_analysis` returns an `UnusedReport` (`unused`, `suppressed`, `diagnostics`) instead of a bare list. `AnalysisResult.suppressed_duplicates` and `suppressed_unused` count findings a directive removed; see [report selection](output.md#report-selection).
- Python is extracted with the exact-pinned `tree-sitter-python` grammar (a new runtime dependency) through the [same backend as every other language](polyglot-languages.md#python). A decorated definition is one unit from its first decorator, so `lineno`, `start_byte`, `start_column`, `source`, fingerprints, identifiers, and the `CodeUnit.uid` byte offset of decorated units move to the `@` line; `source` no longer ends with a newline and `start_column` is the real column.
- Python `native_kind` is `function_definition` or `class_definition` (was `FunctionDef`/`AsyncFunctionDef`/`ClassDef`), and a class defined inside a function is qualified `mod.func.Class` (was `mod.Class`).
- Python identifiers now include attributes and keyword arguments while excluding builtins, keywords, `self`, and `cls`; use `CodeUnit.identifiers` instead of the removed identifier helpers. `CodeUnit.docstring` and `CodeUnit.calls` were removed, while `statement_count` is always extracted.
- The Python `ast` helpers (`compute_ast_hash`, `compute_token_hash`, `count_executable_statements`, `get_exported_names`, `extract_docstring`, `NormalizedASTHasher`, `CallGraphVisitor`, and `_get_module_name`) were removed with that backend; Tree-sitter supplies those features. `get_code_unit_statement_count` returns the extracted count (or `0` for a hand-built unit), and indented unit sources are dedented.
- The exact-duplicate `method` label `ast_hash` is now `structural_hash` in `DuplicatePair.method`, the `--show-all` JSON edge lists, and the CLI table; it names the `CodeUnit.structural_hash` fingerprint every language shares. `HybridDuplicate` records the fingerprint as `exact_method`, and exact pairs now sort ahead of every other hybrid tier, including near pairs that also reach score `1.0`.
- The Python-only `parse-error` diagnostic was replaced by the [shared codes](polyglot-languages.md#source-ranges-and-parse-recovery): a syntax error now yields `partial-parse` plus `unit-parse-error` for the broken unit while intact units are still extracted, and a non-UTF-8 file yields `invalid-utf8` and is analyzed after lossy decoding instead of being skipped.
- Search-only Python callers should use `AnalyzerConfig(mode="search")`; see the [search configuration](python-api.md#semantic-query-search). `analyze()` rejects that mode, while `index()` and `search()` support it.
- Unpinned Hub models use concrete locally resolved commits for cache identity by default. `--loose-revision-cache` opts into label-keyed warm hits that may remain stale after an upstream branch move.
- Runtime dependency minimums changed; use the [installation requirements](install.md). The C2LLM profile and DeepSpeed-only `gpu` extra were removed. Replace `semantic_profiles.resolve_model_name()` with `resolve_model_profile(...).canonical_name`.
- Source archives without VCS metadata build as `0.0.0+unknown`; tagged Git builds retain VCS-derived versions. Source distributions use an explicit file allowlist.
- A pair exact under both fingerprints is now labelled `token_hash` (previously `structural_hash`, since traditional deduplication preferred it), and `exact_families` folds a token clique into its containing `structural_hash` family instead of double-reporting it. `HybridDuplicate.has_exact` was removed; use `exact_method is not None` or the family's `method`.
- The terminal unused table is titled `Potentially Unused` in every mode (combined mode previously said `Likely Dead Code`), and its blurb now states which units the current run excludes; a new `Unused policy: strict|default` summary row matches `--strict-unused`.
- Every terminal table names units by `qualified_name` instead of the bare name, so a shared function name is distinguishable across files and nesting.
- `AnalysisResult.analysis_mode` is now a derived property, not a stored field; it drops `"none"` in favor of `"unused"` for a run where neither traditional nor semantic detection ran (an empty combined run is still `"combined"` with zero counts). `AnalysisResult` gained a required `run: RunRecord` constructor field carrying exactly what the run configured and did; hand-built `AnalysisResult`s must supply it. `AnalyzerConfig` now rejects a config with `run_traditional`, `run_semantic`, and `run_unused` all `False`. See [result types](python-api.md#key-result-types) and [config gates](python-api.md#notes).
- `check --json` and `search --json` drop `summary.extraction_diagnostics` and `summary.semantic_diagnostics` (integer counts); both add a top-level `run` (resolved settings plus derived per-check status) and `analysis_status`, and `search` also adds `summary.extracted_units` and `summary.query_execution`. Read diagnostic counts from `run.checks.*.diagnostics`/`files_failed`; the diagnostic arrays themselves are unchanged. `search_result_to_json` requires a new `run` keyword argument and accepts an optional `query_execution`. See [run record and check status](output.md#run-record-and-check-status).
- A `check`/`search`/`cache` runtime failure (parser unavailable, an unhandled backend exception, a path that disappeared mid-run, or a cache operation that failed outright) now exits `3` instead of `1`, so automation can tell "the command did not complete" from "the command completed and found something" (exit `1`, unchanged) and from a CLI usage error (exit `2`, unchanged). `run_should_fail` gained a `fail_on_incomplete` keyword (default `False`, ORed with the existing policy); `check` gained `--fail-on-incomplete`, which exits `1` when `analysis_status` is not `"complete"`, independent of `--fail-on` including `none`. `check_result_to_json` gained a matching `fail_on_incomplete` keyword, surfaced as `summary.fail_on_incomplete`. See [exit codes](output.md#exit-codes).
- Added `check --unused-only`, mutually exclusive with `--semantic-only`, `--traditional-only`, and `--no-unused`: it disables both duplicate methods (`analysis_mode` becomes `"unused"`, `run.traditional`/`run.semantic` are `null`), loads no embedding model, and rejects any option that only makes sense with duplicate detection running. `--fail-on` semantics are unchanged, so add `--strict-unused` or `--fail-on all` to fail on what an unused-only run finds. An explicit `--max-unused` with `--no-unused` is now also a usage error. See [`check --unused-only`](cli.md#codedupes-check-path).
- Added repeatable `check --focus PATH`, scoping the report and exit code to findings touching one or more paths without changing what the analyzer scans: an exact family is kept whole when any member is in focus, a duplicate pair when either endpoint is, and a `potentially_unused` unit by file. `AnalysisResult` gained a `focus: FocusSummary | None` field and a new exported `focus_result(result, paths)`; `check --json` adds `summary.focus` (`null` when unfocused). Requires a directory target and every focus path inside the scan root. See [focused reports](output.md#focused-reports).

## Detection and extraction

- Added [C, Rust, JavaScript/JSX, and TypeScript/TSX extraction](polyglot-languages.md), and moved Python onto the same Tree-sitter path so all five languages share one fingerprint, identifier, statement-count, and diagnostic implementation. Function and method fingerprints now share a comparison domain; unused analysis remains Python-only.
- Unused analysis now uses a broader [reference graph](analysis-defaults.md#potentially-unused-defaults), including imports, annotations, attributes, and module statements. It analyses every visited Python file, honors package entry points and framework methods, and credits references from a definition the extractor filtered out (a private symbol, or one nested in a filtered-out private container) so what it calls is not misreported as unused. The interpreter recursion limit is raised for the reference walk only, so a deep generated chain that tree-sitter extracts without complaint is analyzed instead of bailed out of; a file that still cannot be read or parsed, or whose nesting overflows even the raised limit (including a parser stack overflow CPython itself raises as `MemoryError`), no longer aborts the scan — it surfaces as an `AnalysisResult.unused_diagnostics` record (`unused-read-error`, `unused-parse-error`, `unused-recursion-limit`) instead of a bare warning.
- `pyproject.toml` entry points are now read from the nearest project above the scan target (a directory root or a single file's own directory), stopping after the git work-tree root, instead of only the exact scan root; a target string with no `module:object` form now credits nothing, replacing the previous bare-last-dotted-segment fallback that could credit an unrelated same-named definition. `build_reference_graph`, `find_potentially_unused`, and the new `find_pyproject` are in `codedupes.unused`; `codedupes.extractor` gained `git_work_tree`.
- A file or directory [skipped only by a default test-file shape](analysis-defaults.md#extraction-scope-defaults) is now still parsed for unused-code references, so a call inside a default-excluded `def test_x(): ...` credits the production code it exercises; a real `--exclude`/`AnalyzerConfig.exclude_patterns` entry, a git ignore rule, or an artifact directory still drops a file from references too. A single-file `check` target resolves the same project-wide reference root used for `pyproject.toml` entry points (nearest `pyproject.toml`, else the git work tree, else the file's own directory) instead of reading references from that one file alone; duplicate detection for a single-file target stays intra-file. `CodeExtractor` gained `reference_only_files` and the public `reference_files()`; `_should_exclude`/`_matches_exclude` gained a `matchers` parameter.
- The test-file and `@abstractmethod` unused-code exemptions now match their intent instead of a loose substring: a file is a test file for the default exclude shapes (`test_*` prefix, `_test`/`_tests` stem suffix) or a pytest `conftest.py`, not any `_test` substring (`legacy_testament.py` no longer qualifies), and a decorator counts as `@abstractmethod`/`@abc.abstractmethod` only as an exact decorator line, not a same-prefix name such as `@abstractmethodish`.
- Python `;` statement separators, optional trailing commas (magic trailing commas included), grouping parentheses, and plain implicit string concatenations are [formatting](polyglot-languages.md#fingerprints-and-comparison-boundaries): they no longer move the structural hash, while the token hash still sees them. Tuple-forming subscript commas remain structural, so `data[key]` and `data[key,]` do not match exactly. A `("doc")` docstring prunes like a bare one; a concatenation with an f-string part is still walked. Formatting policies for C, Rust, JavaScript, and TypeScript are unchanged.
- Python `__all__` accepts bare tuples and module-level `if`/`try` bodies, a definition with no body yields no unit, a filtered private definition of any kind drops its nested definitions, and identifier sets keep the `site`-injected names (`exit`, `quit`, `help`) that are not language builtins.
- Replaced the previous calibration data and compatibility paths with a [versioned manifest and explicit pair contract](../test_fixtures/calibration/README.md) covering runnable Python, C, Rust, JavaScript, and TypeScript applications. Positive pairs span easy, medium, and hard rewrites; nearby negatives and search relevance are reviewed independently.
- Recalibrated both built-in profiles from uncached CPU fp32 measurements, then verified independent MPS fp32 runs. Per-language duplicate gates, search gates, and hybrid visibility constants now use the [checked development-corpus result](../test_fixtures/calibration/calibration-results.json); the [workflow and phase scope](hybrid-tuning.md) explain this first Issue #20 phase, while raw score matrices remain local scratch data.

## Semantic inference and caching

- Recognized local copies and fine-tunes retain their family's tuned thresholds; use `--threshold-profile generic` to restore generic defaults. See [model profiles](model-profiles.md).
- Added persistent [embedding caching](caching.md) and [corpus lifecycle tracking](caching.md#corpus-lifecycle).
- Added explicit CPU/CUDA/MPS selection, dtype control, allocator diagnostics, and bounded OOM recovery. See [accelerator behavior](accelerators.md).
- Added [search indexing, per-query thresholds, and contextual documents](python-api.md#semantic-query-search).
- Long definitions and queries now use normal embedding-backend truncation rather than being excluded from semantic analysis.

## CLI and API output

- Added `search --result-level file` to rank distinct files by their strongest matching code unit, with brief contributing-unit details in terminal and JSON reports. Unit-level search remains the default.
- Added grouped help, `-h`, paired boolean flags, and command-line-only CLI configuration: `CODEDUPES_*` environment variables no longer override options. See [CLI options](cli.md).
- Added configurable [finding exit policies](output.md#exit-codes), [embedding telemetry](output.md#embedding-telemetry), and clean JSON output under merged streams.
- Report selection and JSON serialization are exported from `codedupes`; `run_should_fail` now uses `AnalysisResult.analysis_mode` instead of a caller-supplied `combined_mode` flag. See [report selection](python-api.md#report-selection-and-json).
- Added `check --max-duplicates <N|all>` and `--max-unused <N|all>` (both default `20`) and the `actionable_duplicates`, `reported_actionable_duplicates`, `truncated_by_tier`, `strict_unused`, and `hidden_only_failure` summary fields; the terminal gained an `Exact Duplicate Families` panel, a `Lines` column and size ranking in the unused table, an `Actionable duplicates` row, and `Truncated duplicates` / `Truncated unused` rows that name the cut tiers. `ExactFamily`, `build_exact_families`, `DEFAULT_MAX_UNUSED`, and `unused_sort_key` are exported. See [report selection](output.md#report-selection).
- Added `check --source-lines <N|all>` (default `40`); it bounds every `--show-source` snippet, terminal and JSON alike, and implies `--show-source` on its own. `--show-source` now also works with `--json`, adding `source` and `source_lines_omitted` to every unit record instead of being rejected; `check_result_to_json` and `unit_to_dict` gained matching `include_source`/`source_lines` keyword arguments, both opt-in, so default payloads are unchanged. `CodeUnit.source_lines(limit)` replaces the removed `cli._render.truncate_source`.
- Added `check --show-diff`, a unified source diff per duplicate pair bounded by `--source-lines`: exact families diff each member against the first when their source differs, and `--json` rejects the flag like the other rich-only display controls.
- Added a resolved `run` record and derived per-check status (`AnalysisResult.run`/`checks`/`analysis_status`, `CodeAnalyzer.run_record`) describing exactly what a run configured and completed, independent of what it found. `check` prints a `Run` panel before the summary and adds an `Analysis status` summary row; `check --json`/`search --json` add top-level `run` and `analysis_status`, and `run.units` breaks the extracted corpus down by language and unit type (`by_language`, `by_type`), so JSON carries the same counts as the terminal summary. `search --json` also adds `summary.extracted_units` (the pre-eligibility-filter extraction count) and `summary.query_execution`, distinguishing an empty repository from an index that semantic eligibility filtering emptied. See [run record and check status](output.md#run-record-and-check-status).
- Every `check --json`/`search --json` payload now leads with a top-level `about` block (`description`, `docs`, `repository`, `tool`), so a report saved without other context still identifies what produced it.
- `--traditional-only`'s raw table is retitled `Near Duplicates (Jaccard)`, since exact pairs already live in the `Exact Duplicate Families` panel and never appear there.
